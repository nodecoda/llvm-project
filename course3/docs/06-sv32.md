# 第 06 章：Sv32 分页

## 目标

让 U 态的每一次取指、load 和 store 都经过页表：

- `satp.MODE=1` 时，U 态走 Sv32 两级页表；M 态始终使用物理地址；
- 4 KiB 页：`VPN1 → 根表`、`VPN0 → 二级表`、页内偏移 12 位；
- 权限：`V/R/W/X/U/A/D`；`U=0` 的页不能被 U 态访问，`W=1 && R=0` 视为非法；
- 页错误 cause：取指 12、load 13、store 15；`mtval` 是出错**虚拟地址**；
- `A/D` 由软件维护：`A=0` 的任何访问、`D=0` 的 store 都触发页错误；
- `--dump-pagetable [<satp>]` 按 `satp` 遍历页表，打印非零叶子；
- 同一个 U 程序在“恒等映射”和“VA `0x10000` → PA `0x80400000`”下输出一致；
- 门禁从 11 项增加到 **14 项**，`--selftest` 从 22 项增加到 **32 项**。

这一章不做超级页、TLB、`sfence.vma`、`MPRV/SUM/MXR`；它们放进练习与第 10 章的
“未做清单”。

## 背景：satp、VPN 与 PTE

Sv32 把一个 32 位虚拟地址切成三段：

```text
 31        22 21        12 11         0
+------------+------------+------------+
|   VPN1     |   VPN0     |   offset   |
|  (10 bit)  |  (10 bit)  |  (12 bit)  |
+------------+------------+------------+
```

根表有 1024 个 4 字节 PTE，二级表也有 1024 个。一个 PTE 的布局：

| 位 | 名称 | 本章含义 |
| --- | --- | --- |
| 31:10 | PPN | 物理页号；PA = `PPN << 12` |
| 9:8 | RSW | 保留，忽略 |
| 7 | D | dirty；store 要求为 1 |
| 6 | A | accessed；任何访问都要求为 1 |
| 5 | G | global，忽略 |
| 4 | U | U 态可访问 |
| 3 | X | 可执行 |
| 2 | W | 可写 |
| 1 | R | 可读 |
| 0 | V | 有效 |

`satp` 的低 22 位是根表的 PPN：

```text
 31    30        22 21                    0
+---+--------------+-----------------------+
|MODE|    ASID     |          PPN          |
+---+--------------+-----------------------+
```

`MODE=1` 是 Sv32，`MODE=0` 是 Bare（不翻译）。本课只实现 Sv32 的 4 KiB 页。

### 为什么 M 态不翻译

RISC-V 规定 M 态在 `MPRV=0` 时使用物理地址。内核写 `satp` 之后仍然要在
`0x80000000` 上继续取指、读写自己的栈和页表；如果 M 态也翻译，内核必须先把
自己恒等映射好，启动顺序会多一层。本课把这条规则直接写进 `Machine::translate()`：

```cpp
if (priv_ == Priv::M)
  return va; // 物理地址，连 satp 都不看
```

U 态才进入 `Mmu::translate()`；`satp.MODE=0` 时 U 态也是 Bare。

### 为什么 A/D 由软件维护

规范允许硬件自动置 `A/D`，也允许触发页错误让软件处理。本课选择后者：

- 门禁可以精确观察 `A=0`、`D=0` 的页错误；
- 读者能亲手算出“第一次访问会 fault，置位后才成功”；
- 不需要在 walker 里偷偷写内存，页表遍历保持只读。

代价是内核必须在建表时把 `A/D` 置好；本课的两个测试都显式写了 `A=1`，
需要写的页再写 `D=1`。

## 关键实现

### 1. 翻译发生在取指和访存助手里

```cpp
uint32_t Machine::translate(uint32_t va, AccessType type, uint32_t epc) const {
  if (priv_ == Priv::M)
    return va;
  if ((csr_[kCsrSatp] & kSatpMode) == 0)
    return va;
  return Mmu::translate(bus_->ram(), csr_[kCsrSatp], va, type, epc);
}
```

- 取指：`fetchWord(pc)` 先把 `pc` 翻译成 PA，再从总线取 32 位；
- load/store：`load8/16/32`、`store8/16/32` 先翻译，再访问总线；
- `mepc`、分支目标、`mtval` 全部保持**虚拟地址**，只有总线看到 PA；
- 页错误在 `Mmu::translate()` 里直接抛 `Trap`，`step()` 的 catch 统一进
  `enterTrap()`，所以 cause/epc/tval 与第 03 章的精确陷阱模型完全一致。

### 2. 两级 walk

```cpp
const uint32_t root = (satp & 0x003fffffu) << 12;
const uint32_t vpn1 = (va >> 22) & 0x3ff;
const uint32_t pte1 = readPte(ram, root + vpn1 * 4, ...);
if (!(pte1 & kPteV)) pageFault(...);
if (pte1 & (kPteR | kPteW | kPteX)) pageFault("superpage");

const uint32_t level1 = (pte1 & kPtePpnMask) << 2;
const uint32_t vpn0 = (va >> 12) & 0x3ff;
const uint32_t pte0 = readPte(ram, level1 + vpn0 * 4, ...);
...
return ((pte0 & kPtePpnMask) << 2) | (va & kPageMask);
```

`kPtePpnMask = 0xfffffc00` 取出的是 **PPN 左移 10 位后的值**；要变成物理地址，
必须再左移 2 位（等价于 `(pte >> 10) << 12`）。这一步写错时，walker 会把
`0x20004400` 当成地址去读，报“page-table page is unmapped”——本章真实踩过这个坑。

`readPte()` 把 `rsim::MemoryError` 也翻译成页错误：页表页本身没映射时，
访问者看到的是 cause 12/13/15，而不是宿主异常。

### 3. 权限检查的顺序

```cpp
if (!r && !w && !x)                 pageFault("non-leaf at level 0");
if (w && !r)                        pageFault("W=1 with R=0");
if (!(pte & kPteU))                 pageFault("U=0");
if (type == Fetch && !x)            pageFault("not executable");
if (type == Load  && !r)            pageFault("not readable");
if (type == Store && !w)            pageFault("not writable");
if (!(pte & kPteA))                 pageFault("A=0");
if (type == Store && !(pte & kPteD)) pageFault("D=0");
```

cause 只看访问类型：

| 访问 | cause |
| --- | --- |
| 取指 | `InstructionPageFault = 12` |
| load | `LoadPageFault = 13` |
| store | `StorePageFault = 15` |

`mtval` 一律是出错虚拟地址；取指页错误的 `mepc` 是那条取不到的指令地址。

### 4. 同一 blob，两种映射

`tests/mmu-run.c` 把 `u-blob.S` 的机器码复制到 PA `0x80400000`，然后建两张根表：

| 阶段 | 根表项 | 二级表项 | 结果 |
| --- | --- | --- | --- |
| 1 | `root[0x200] → l1_id` | `l1_id[1] → PA 0x80400000, U/R/X/A` | VA `0x80001000` 可执行 |
| 2 | `root[0x000] → l1_reloc` | `l1_reloc[0x10] → 同一个 PA` | VA `0x00010000` 可执行 |

两张表都把 UART 页 `0x10000000` 映射成 `U/R/W/A/D`。U blob 只用
`li`/`sb`/`ecall`，没有任何绝对数据引用，所以复制到新 PA 后仍能运行：

```asm
li      t0, 0x10000000
li      t1, 'U'
sb      t1, 0(t0)
...
li      a7, 93
ecall
```

第一次 `ecall` 后，M 态 handler 把 `satp` 换成第二张根表、把 `mepc` 设为
`0x00010000`，再 `mret`。两次都输出 `U ok\n`，所以 golden 是两行。

> 注意：U blob 的代码页是 `U/R/X/A`，**没有 W、没有 D**；它只取指和读，
> 不写自己的页。UART 页才有 `W/D`。

### 5. 端到端的 load page fault

`tests/mmu-fault.c` 把内核页 `0x80000000` 映射成 `R/W/X/A/D` 但 **`U=0`**，
U blob 执行：

```asm
li t0, 0x80000000
lw t1, 0(t0)      # U=0 -> cause 13
```

handler 只在 `cause == 13` 时写 `0x5555`，否则写 `0x7777`。因此宿主退出码 0
同时证明了三件事：U 态取指成功、load 经过了翻译、页错误的 cause 是 13。

### 6. `--dump-pagetable`

```text
satp 0x80080002 mode=1 asid=0x000 ppn=0x080002
leaf va=0x00010000 pa=0x80400000 pte=0x2010005b level=0 flags=VRXUA
leaf va=0x10000000 pa=0x10000000 pte=0x040000d7 level=0 flags=VRWUAD
```

- 不带参数：用程序停机时的 `satp`；
- 带参数：`--dump-pagetable 0x80080003` 可以看另一张根表；
- `level=1` 表示在根表就遇到叶子（4 MiB 超级页），`translate()` 会拒绝它；
- 输出按 VA 升序，最多 64 条，避免一个 4 GiB 恒等映射刷屏。

### 7. 用户物理页 arena

`Machine::reset()` 在 DRAM 里多映射 64 KiB：

```cpp
bus_->ram().map(kUserBase, kUserSize); // 0x80400000, 64 KiB
```

第 06 章用它放 U blob；第 07 章会把用户 ELF 的每个 `PT_LOAD` 复制到这里，
再把页表指向这些物理页。内核自己的页表数组在 `.bss`，由镜像的 `PT_LOAD`
一并映射。

## 构建与验证

```bash
W=/home/ubuntu/llvm/trees/pr-ctpop
B=/home/ubuntu/llvm/builds/pr-ctpop

ninja -C "$B/course3"
"$W/course3/scripts/course3-verify.sh" "$B/bin" "$B/course3/rmach"
```

门禁 14 项，第 06 章新增 3 项：

1. `mmu-run`：stdout 逐字节等于 `U ok\nU ok\n`，退出码 0；
2. `--dump-pagetable`：出现 `mode=1`、重定位 U 页和 UART 页两个叶子；
3. `mmu-fault`：U 读 `U=0` 页，handler 只接受 cause 13，退出码 0。

`--selftest` 新增 10 条 Sv32 向量（总共 32 条），覆盖：

- 正常 load/fetch 翻译；
- `U=0`、不可执行、只读、`A=0`、`D=0`、`W=1 && R=0`；
- 无效根 PTE、未映射页表页、超级页拒绝。

`satp` 的 PPN、页表数组的物理地址以及指令数会随链接布局变化；门禁只断言
stdout、叶子映射和退出码。

## 常见坑

1. **把 `pte & 0xfffffc00` 直接当地址**。它是 `PPN << 10`，还要 `<< 2` 才是
   `PPN << 12`。写错时 walker 读到一个不存在的“页表页”，报
   `page-table page is unmapped`，看起来像 RAM 没映射，实际是位域算错。
2. **U 页忘了 `U=1`**。只写 `V/R/W/X/A/D` 时，M 态看着一切正常，U 态第一条
   取指就 cause 12。本章的 `mmu-fault` 正是利用这一点故意让 `U=0`。
3. **`A/D` 以为硬件会置位**。本课不置位；`A=0` 连 load 都会 fault，
   `D=0` 只拦 store。建表时先写 `A/D`，否则调试信息会非常反直觉。
4. **`W=1, R=0`**。规范保留这种组合；本章按非法 PTE 处理。写只读页时不要
   只清 `W` 忘了 `R` 还在。
5. **U 态用物理地址当 `mepc`**。`mret` 的 `mepc` 必须是虚拟地址；重定位阶段
   要跳到 `0x10000`，不是 `0x80400000`。
6. **U blob 不是位置无关的**。复制到新 PA 后，任何 `la symbol` 或绝对数据
   引用都会指向链接地址，而不是新 VA。本章的 blob 只用 `li`/`sb`/PC 相对
   控制流，就是为了能在两个 VA 下运行。
7. **内核 C 代码用了 `gp`**。`start.S` 没有初始化 `gp`；如果编译时允许
   small-data，访问静态数组会走 `gp=0`，直接 access fault。门禁统一加
   `-msmall-data-limit=0`，把这个隐患消掉。
8. **在 U 态停机后读 `satp`**。`readCsr()` 会做特权检查；`--dump-pagetable`
   走的是 `Machine::satp()` 这个调试访问器，不经过 U 态检查。
9. **页表数组没对齐**。根表和二级表必须是 4 KiB 对齐；`aligned(4096)` 配合
   链接脚本的 `.bss` 对齐，`llvm-nm` 里能看到 `80002000`/`80003000` 这样的地址。
10. **忘了 `satp.MODE`**。只写 PPN 不写 bit 31，U 态仍然 Bare，程序会按
    物理地址跑，看起来“页表没生效”。

## 练习

1. 实现 4 MiB 超级页：根表叶子直接映射 `PA = PPN << 12 | (VA & 0x3fffff)`，
   并让 `--dump-pagetable` 打出 `level=1`。
2. 让硬件在 walk 时自动置 `A/D`，比较“第一次访问是否 fault”的差异。
3. 增加 `--dump-pagetable --va 0x10000`，只打印命中某个 VA 的路径。
4. 给 `mmu-fault` 加 store 只读页（15）、取指不可执行页（12）、`A=0`（13）
   三个变体，把 selftest 的单元证据变成端到端证据。
5. 加一个 8 项 TLB，用 `satp` 的 ASID 做 tag，并实现 `sfence.vma` 清表。
6. 实现 `mstatus.MPRV`：M 态用 U 的权限翻译一次 load/store，观察 `SUM/MXR`。
7. 把 `mmu-run` 的 U blob 改成 rvmin 编译的用户程序，为第 07 章铺路。
