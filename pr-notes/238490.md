## 2. 根因

`#236404`（已合并且仍在 `upstream/main`）把 `getFConstantVRegValWithLookThrough()` 改成优先按
`G_FCONSTANT` 自身的 semantics 读取常量，而不是按位宽猜 IEEE 格式。结果是：同一条指令的
两个操作数可以分别按 **half** 和 **bfloat** 解释，而 `APFloat::compare()` 要求两边
`semantics` 指针相同：

```cpp
assert(&getSemantics() == &RHS.getSemantics() &&
       "Should only compare APFloats with the same semantics");
```

- assertions 构建：断言失败，编译崩溃。
- release 构建：断言被编译掉，`IEEEFloat::compare` 用左值的 semantics 解释两边已按各自格式
  解码的字段，**结果无意义，属于静默 miscompile**。

同一个 16 位模式的两种含义（`f16` = 1+5+10，`bf16` = 1+8+7）：

| bits | half | bfloat |
| --- | --- | --- |
| `0x3C00` | 1.0 | 2^-7 = 0.0078125 |
| `0x3F80` | 1.875 | 1.0 |
| `0x7E00` | NaN | 2^125 |
| `0x4000` | 2.0 | 2.0（幂次恰好重合） |

一旦值进入普通 `s16` 寄存器，类型系统就不再携带格式；经过 `G_TRUNC/G_SEXT/G_ZEXT` 改宽度
后连 `G_FCONSTANT` 的原始格式也会丢失。因此“两边格式不一致就不折叠”是保守且正确的处理。

## 3. 修复评审

两处守卫：

- `llvm/lib/CodeGen/GlobalISel/CombinerHelperCompares.cpp:75`（`constantFoldFCmp`），只作用于
  scalar `G_FCMP`；vector 常量在此之前已返回 false。
- `llvm/lib/Target/AMDGPU/AMDGPURegBankCombiner.cpp:276`（`matchFPMinMaxToMed3`），短路求值
  保证格式不同时不会执行 `K0->Value > K1->Value`。

判定方式正确：`fltSemantics` 是单例，`APFloat` 自身契约就是比较指针。

`getFltSemanticForLLTOrNull`（`LowLevelTypeUtils.cpp:123`）把 16/32/64/128 的列表收敛到一处，
`getFltSemanticForLLT` 行为保持不变（`llvm_unreachable` 语义等价），`LLVM_ABI` 标注正确。

## 4. 发现的问题

### P1：clamp 路径漏了同类守卫（可能 miscompile）

`matchFPMinMaxToClamp`（`AMDGPURegBankCombiner.cpp:312`）和
`matchFPMed3ToClamp` / `isClampZeroToOne`（`:649`）不做“两常量互相比较”，不会撞断言，
但它们按常量自身格式调用 `isOne()`，随后丢弃常量、生成 `G_AMDGPU_CLAMP`：

- `K1` 为 `bf16 1.0`（bits `0x3F80`），而 min/max 的 dst 是 `s16`（f16 指令）时，`isOne()` 为真；
- `applyClamp()` 发出 `G_AMDGPU_CLAMP`，isel 按 dst 选 `ClampPat<V_MAX_F16_e64, f16>`
  （`SIInstructions.td:2090`），硬件 clamp 的 1.0 是 f16 `0x3C00`；
- 原语义 `min(x, 0x3F80)` = f16 的 1.875 被换成 clamp 到 1.0，`x ∈ (1.0, 1.875)` 结果错误。

`K0->isPosZero()` 不受影响：±0 的位模式跨格式一致。问题只在 `isOne()` 一侧。
PR 自带的 `clamp_bf16_half_one_bits` 只覆盖了反方向（`0x3C00` 在 bf16 下不是 1.0 → 不合并）。

建议：clamp 匹配要求 `K1->Value.getSemantics()` 等于 dst 标量类型的 semantics
（`s16 → half`，`bf16 → bfloat`），或改为按指令类型检查位模式。

### P2：单常量谓词的格式假设

同类问题还存在于按常量自身格式求值的单常量谓词，例如 `CombinerHelper.cpp:7002` 的
`isNonZero()`（`matchFPSelectToMinMax` 的 ±0 规避）。bf16 次正规数在 f16 下可能为 0，
结论会相反。优先级低，但根因相同。

### P3：修复尚未进入 trunk

核对 `upstream/main`：没有 `getFltSemanticForLLTOrNull`，两处守卫也都不存在；`#236404` 已在。
即 main 仍有该断言/wrong-code 风险。`#220807` 仍 OPEN。
