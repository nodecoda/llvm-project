# 第 25 章：f32——同一条流水线里的浮点

## 目标

第 24 章把 i32 的 `Python -> TTIR -> LLVM IR -> GM32 -> sim` 打通了。
这一章不新建流水线，只把 **f32** 放进同一条流水线：

1. GM32 增加 `fadd/fsub/fmul`（opcode `0x07`）和 `fsetp`（opcode `0x0A`）；
2. TTIR 增加 `arith.addf/subf/mulf` 与 `arith.cmpf`；
3. 前端识别 `--arg-type NAME=f32`、`ptr<f32>` 和 Python 浮点字面量；
4. 模拟器按 IEEE-754 单精度执行浮点；kernel 参数仍是 `sr.args` 的 32 位字。

退出条件（可执行）：

```sh
llvm/lib/Target/GPUMin/scripts/check-ch25.sh <llvm-bin-dir>
```

## ISA：一个寄存器文件，两种解释

GM32 没有独立的浮点寄存器堆。`r0..r31` 里的 32 位模式既可以是 i32，
也可以是 f32；**opcode 决定解释方式**：

| opcode | funct | 指令 | 含义 |
| --- | --- | --- | --- |
| `0x02` | 0..7 | `add/sub/and/or/xor/shl/shr/sar` | 整数 ALU |
| `0x07` | 0/1/2 | `fadd/fsub/fmul` | IEEE-754 单精度 |
| `0x03` | 0..D | `setp.*` | 整数谓词比较 |
| `0x0A` | 0..5 | `fsetp.oeq/one/olt/ole/ogt/oge` | ordered 浮点谓词比较 |

编码是 R2 格式：`[31:26] opcode | [25:21] rd | [20:16] rs1 | [15:11] rs2 | [10:0] funct`。
`fsetp` 复用谓词文件 `p0..p7`，所以 `setp` 之后的所有 `selp`/`bra` 逻辑不用改。

```text
fadd  r1, r2, r3   ->  0x1c221800  (opcode 0x07, funct 0)
fsetp.olt p1, r2, r3 -> 0x28221800  (opcode 0x0A, funct 2)
```

## 为什么 f32 能复用 i32 的 load/store

`ld.global.b32` / `st.global.b32` 搬的是 32 位原始模式，不关心它是整数还是浮点。
f32 的访存只需要在 DAG 里把值类型标成 `f32`：

```tablegen
def : Pat<(f32 (load i32:$base)), (LD_GLOBAL_B32 $base, 0)>;
def : Pat<(store f32:$val, i32:$base), (ST_GLOBAL_B32 $val, $base, 0)>;
```

shared/local/constant 空间由手写选择器处理；`pickLoadOpcode` 里
`MVT::f32` 与 `MVT::i32` 落到同一个 `B32` opcode。

## TTIR：addf / mulf / cmpf

Python 的二元运算先按语法选 opcode，再按操作数类型改写：

```text
x + y       (tensor<256xf32>)  -> arith.addf %x, %y : tensor<256xf32>
x * 1.5                        -> arith.constant 1.500000e+00 : f32
                                  tt.splat ...
                                  arith.mulf ...
x < y                          -> arith.cmpf olt, %x, %y : tensor<256xf32>
```

Python 的 `==/!=/</<=/>/>=` 对浮点映射到 **ordered** 谓词：

| Python | TTIR | GM32 |
| --- | --- | --- |
| `==` | `cmpf oeq` | `fsetp.oeq` |
| `!=` | `cmpf one` | `fsetp.one` |
| `<` | `cmpf olt` | `fsetp.olt` |
| `<=` | `cmpf ole` | `fsetp.ole` |
| `>` | `cmpf ogt` | `fsetp.ogt` |
| `>=` | `cmpf oge` | `fsetp.oge` |

unordered 谓词（NaN 相关）不进入 ISA：`GPUMinISelLowering.cpp` 在合法化阶段
把它们展开成 ordered 比较加逻辑运算。

## 浮点字面量：JSON 分不清 2 和 2.0

CPython AST 的 `Constant` 里 `2.0` 是 float，但 `llvm::json` 的
`getAsInteger()` 会把整数值的 double **规范化成 int64**。如果前端只看
`getInteger`，`x * 2.0` 会悄悄变成整数乘法。

修法是在 AST 桥里记录 Python 类型：

```python
if isinstance(node, ast.Constant) and isinstance(node.value, float):
    out["value_is_float"] = True
```

前端先看这个标记，再读 `getNumber`。这一条也解释了为什么教程坚持
“AST JSON 的 schema 是契约”：类型信息必须在桥上有明确表示。

## LLVM emitter：参数块与常量

kernel 仍没有形式参数，参数块是 32 位字数组。f32 参数按位模式读出后
`bitcast`，不做数值转换：

```llvm
%raw = load i32, ptr addrspace(1) %slot
%x = bitcast i32 %raw to float
```

浮点常量不落到 constant pool。后端重写了
`getFPImmAction`，对 f32 返回 `FPImmAction::Legal`，选择器用
`movi/shl/shr/or` 把 32 位模式直接materialise 到 GPR：

```cpp
FPImmAction GPUMinTargetLowering::getFPImmAction(...) const {
  if (VT == MVT::f32)
    return FPImmAction::Legal;
  return TargetLowering::getFPImmAction(Imm, VT, ForCodeSize);
}
```

这避免了“每个字面量一次常量池 load”，也让 `-O0` 和 `-O1` 的代码形状一致。

## 模拟器：每次都 round-trip 到单精度

Python 的 `float` 是 double。如果直接用它算，`1.0 + 1e-8` 会保留 double
精度，和硬件不一致。模拟器对每个 f32 运算做一次：

```python
def f32_to_bits(value):
    return struct.unpack("<I", struct.pack("<f", value))[0]
```

`fsetp` 用 `math.isnan` 显式实现 ordered 语义：任一操作数是 NaN 时，
六个 ordered 谓词全部为假。

## 跑一遍 f32 vecadd

```python
@triton.jit
def f32_add(x_ptr, y_ptr, out_ptr, BLOCK: tl.constexpr):
    offs = tl.arange(0, BLOCK)
    x = tl.load(x_ptr + offs)
    y = tl.load(y_ptr + offs)
    tl.store(out_ptr + offs, x + y)
```

```sh
gpumin-triton --emit-ttir --constexpr BLOCK=256 \
  --arg-type 'x_ptr=ptr<f32>' --arg-type 'y_ptr=ptr<f32>' \
  --arg-type 'out_ptr=ptr<f32>' scripts/triton/f32_add.py
```

第 25 章门禁覆盖两段真实程序：

1. `f32_add.py`：256 元素的 f32 vecadd，sim 输出与逐元素参考位模式一致；
2. `f32_scale.py`：`x * 1.5`、`x < y`、masked store，覆盖 `fmul`、
   `fsetp.olt` 和 f32 比较产生的谓词分支。

第二个 kernel 的乘法常数特意选 1.5：`x * 2.0` 会被 DAG combine 改写成
`fadd x, x`，那样就测不到 `FMUL` 了。这是教程里一个值得记住的细节。

## 已知边界

- 只做 `+/-/*`；`/`、`exp`、`sqrt` 留到第三课（需要新的 ISA 或近似序列）。
- 不承诺 NaN/denormal 的测试矩阵；模拟器已经按 IEEE 实现，但课程测试值
  只取可精确表示的有限数。
- 没有 `f64`：GM32 的一个寄存器就是 32 位。
- `BLOCK <= 256` 是当前寄存器压力的稳定上限（第 24 章已记录）。
