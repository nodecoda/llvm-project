# 第 11 章：端到端、测试体系与教程收尾

## 目标

前十章每一章都只验证自己新增的那一小块。本章做三件事：

1. 把后端放回**真实链路**里：`clang → IR → llc → .s → 汇编器 → .o`，
   一份 C 语料、四个优化级别、逐字节比对；
2. 补上真实代码暴露出来的三个缺口（`.eh_frame`、`switch`、`LUI` 打印）；
3. 给出一套可重复的门禁，和“接下来怎么改”的地图。

这一章的价值在于：**前十个门禁全绿并不等于能编译真实程序**。下面这三个问题，
只有把语料跑起来才会出现。

| 问题 | 触发条件 | 现象 |
| --- | --- | --- |
| 跳转表 | `switch` + `-O0` | `Cannot select: br_jt` / `brind` |
| CFI 缺失 | 需要 `.eh_frame` 的函数 | CIE 没有 CFA 规则，FDE 缺 `ra` |
| LUI 立即数 | 常量高位 ≥ 0x80000（如 `0xEDB88320`） | `llvm-mc` 拒绝自己的输出 |

## 关键实现

### 1. CFI：让 `.eh_frame` 说实话

`.eh_frame` 是“任意一条指令处如何找回寄存器和返回地址”的表。它的两半：

- **CIE**（每个编译单元一份）：CFA 的定义（这里是 `sp + 0`）、返回地址列；
- **FDE**（每个函数一份）：在哪些地址上 CFA 偏移多少、哪些寄存器存在哪里。

第一版后端的 `.eh_frame` 只有一个空 FDE：没有 CFA、没有 `ra`。对“不抛异常、
不 unwind”的程序没影响，但任何 backtrace、`-funwind-tables`、C++ 异常都会读到
垃圾。三处修复：

**① CIE 需要初始规则。** 目标要在 `MCAsmInfo` 里声明“进入函数时 CFA 就是 sp”：

```cpp
unsigned SP = MRI.getDwarfRegNum(RVMin::X2, /*IsEH=*/true);
MAI->addInitialFrameState(MCCFIInstruction::cfiDefCfa(nullptr, SP, 0));
```

**② CIE 的返回地址列必须是 `ra`。** 它来自 `createRVMinMCRegisterInfo` 的第二个
参数。第 2 章还没有 `ra`，那里传的是 `RVMin::X0`：

```cpp
InitRVMinMCRegisterInfo(X, RVMin::X1);   // 第 2 章是 X0
```

`X1` 的 DWARF 号是 1，于是 CIE 里 `return_address_register: 1`。

**③ FDE 需要随着 `sp` 移动更新。** 在 prologue 的存寄存器**之后**发：

```
addi  sp, sp, -16
sw    ra, 12(sp)
sw    s0, 8(sp)
.cfi_def_cfa_offset 16      # CFA 现在是 sp + 16
.cfi_offset ra, -4          # ra 存在 CFA - 4
.cfi_offset s0, -8
```

epilogue 里对称地 `restore`：

```
lw    ra, 12(sp)
lw    s0, 8(sp)
addi  sp, sp, 16
.cfi_restore ra
.cfi_restore s0
.cfi_def_cfa_offset 0
```

一个细节：**CFI 指令必须放在 store 之后**。放在之前，unwinder 会在 store 尚未执行
时就认为寄存器已经保存好了（信号在 prologue 里到达时就会读到垃圾）。所以
`emitPrologueCFI` 先跳过所有带 `FrameSetup` 标志的指令，再插入：

```cpp
  MachineBasicBlock::iterator CFIPos = MBB.begin();
  while (CFIPos != MBB.end() && CFIPos->getFlag(MachineInstr::FrameSetup))
    ++CFIPos;

  CFIInstBuilder CFIBuilder(MBB, CFIPos, MachineInstr::FrameSetup);
  CFIBuilder.buildDefCFAOffset(StackSize);
  for (const CalleeSavedInfo &CS : MFI.getCalleeSavedInfo())
    CFIBuilder.buildOffset(CS.getReg(), MFI.getObjectOffset(CS.getFrameIdx()));
```

`getObjectOffset()` 本身就是“相对 CFA”的偏移（帧向下生长时为负），所以不需要再
加栈大小。这一点很容易写错，用 `llvm-readelf --unwind` 一看便知：

```
  [0x0] CIE length=16
    return_address_register: 1
    Program:
      DW_CFA_def_cfa: reg2 +0

  [0x14] FDE length=28
    Program:
      DW_CFA_advance_loc: 12 to 0xc
      DW_CFA_def_cfa_offset: +16
      DW_CFA_offset: reg1 -4
      DW_CFA_offset: reg8 -8
      DW_CFA_advance_loc: 44 to 0x38
      DW_CFA_restore: reg1
      DW_CFA_restore: reg8
      DW_CFA_def_cfa_offset: +0
```

**什么时候才会有 `.eh_frame`？** 由 `MachineFunction::needsFrameMoves()` 决定：

```cpp
  return getTarget().Options.ForceDwarfFrameSection ||
         F.needsUnwindTableEntry() ||          // uwtable 或"可能抛异常"
         !F.getParent()->debug_compile_units().empty();
```

所以：手写 IR（没有 `nounwind`）会生成；clang 的 C 代码默认**不**生成
（有 `nounwind`），要 `-funwind-tables` 或 `-fexceptions` 才有。这解释了为什么
"我加了 CFI 但汇编里没有"。

### 2. `switch`：跳转表不是免费的

`-O0` 的语料让后端崩在：

```
LLVM ERROR: Cannot select: t4: ch = br_jt t2:1, JumpTable:i32<0>, t2
```

IR 的 `switch` 会被翻译成两种形态之一：比较链，或跳转表（`.rodata` 里一张
代码标签数组 + 一次 `ld` + 一次间接跳转）。选择由 `SwitchLowering::areJTsAllowed`
决定：

```cpp
  bool areJTsAllowed(const Function *Fn) const {
    return TLI.isOperationLegalOrCustom(ISD::BR_JT, MVT::Other) ||
           TLI.isOperationLegalOrCustom(ISD::BRIND, MVT::Other);
  }
```

两个节点默认都是 `Legal`，于是默认就会造跳转表。RVMin 既没有标签表也没有间接
跳转，所以两者都必须显式关掉：

```cpp
  setOperationAction(ISD::BR_JT,  MVT::Other, Expand);
  setOperationAction(ISD::BRIND, MVT::Other, Expand);
```

关掉之后 `switch` 在任何优化级别都降级为 `beq/bne` 比较链——慢一点，但正确。
（真要做跳转表，需要 `TargetLowering::getJTISymbol`、AsmPrinter 发
`.word .LBB...`，以及一条 `jalr zero, 0(reg)` 的 `BRIND` 选择。这是第 13 章的
候选题目。）

### 3. LUI 的立即数：一个只会在往返比对里暴露的 bug

语料 `crc32.c` 里有 `0xEDB88320`，`-O0` 生成：

```
lui a2, -74872
```

然后 `llvm-mc` 拒绝：

```
error: operand must be a symbol with %hi/%tprel_hi specifier or an integer
       in the range [0, 1048575]
```

原因：DAG 里的常量是**符号扩展的 i32**，`0xEDB88` 这个 20 位域值被表示成
`-74872`。编码器截断到 20 位是对的（`-74872 & 0xFFFFF == 0xEDB88`），所以这是
纯打印/解析问题——但“自己的汇编器读不了自己的输出”是必须修的门禁级 bug。

修法：给 `uimm20` 一个专用打印方法，永远打印无符号 20 位域，并在谓词里同时接受
两种表示：

```tablegen
def uimm20 : Operand<i32> {
  let PrintMethod = "printUImm20Operand";
  let ParserMatchClass = UImm20AsmOperand;
  let MCOperandPredicate = [{
    int64_t Imm;
    return MCOp.evaluateAsConstantImm(Imm) && (isUInt<20>(Imm) || isInt<20>(Imm));
  }];
```

```cpp
void RVMinInstPrinter::printUImm20Operand(...) {
  if (MO.isImm()) { O << (MO.getImm() & 0xFFFFF); return; }
  MAI.printExpr(O, *MO.getExpr());   // %hi(sym) 仍然按符号打印
}
```

现在输出是 `lui a2, 973704`（与 GNU as / `llvm-mc` 的 RISC-V 语法一致），往返
比对通过。这一条很值得记住：**编码正确 ≠ 文本正确**，两条路都要门禁。

## 测试体系

四层门禁，从最内层到最外层：

| 层 | 命令 | 覆盖什么 | 本章结果 |
| --- | --- | --- | --- |
| MC 编码 | `scripts/check-rvmin-encodings.sh` | 83 条指令与参考汇编器逐字节一致（含标签、`%hi/%lo`）；第 12 章加入 `ecall`/`ebreak` 后为 85 条 | PASS |
| CodeGen 单测 | `llvm-lit llvm/test/CodeGen/RVMin` | 每章语义 FileCheck、`-O0` 崩溃检查、重定位 | 9/9 |
| 优化级别扫描 | `llc -O0..-O3 -verify-machineinstrs` | 机器 IR 合法性、不同优化路径 | 0 失败 |
| 端到端 | `scripts/rvmin-e2e.sh` | clang → obj、ELF 类型、`.text` 往返逐字节 | 28 个对象 / 14824 字节 |

端到端脚本的核心是这样一个循环（7 个程序 × 4 个优化级别）：

```bash
for c in scripts/e2e/*.c; do
  for O in 0 1 2 3; do
    clang --target=riscv32-unknown-elf -march=rv32i -mabi=ilp32 -O$O \
      -S -emit-llvm "$c" -o prog.ll
    llc -march=rvmin -mtriple=riscv32-unknown-elf -O$O -verify-machineinstrs \
      prog.ll -filetype=obj -o a.o          # ① 对象文件
    llc -march=rvmin -mtriple=riscv32-unknown-elf -O$O prog.ll -o a.s
    llvm-mc -triple=riscv32-unknown-elf -filetype=obj a.s -o b.o   # ② 往返
    objcopy --only-section=.text a.o a.bin && objcopy ... b.o b.bin
    cmp a.bin b.bin                          # ③ 逐字节
  done
done
```

语料本身也是有讲究的，7 个程序分别压一类功能：

| 程序 | 压测点 |
| --- | --- |
| `arith.c` | 乘除取模、64 位、移位、位内建 |
| `control.c` | 分支、循环、`switch`、递归 |
| `memory.c` | 数组、指针、结构体、字符串、静态数据、`memcpy` |
| `types.c` | `char`/`short`/`_Bool`/`long long`、窄访存 |
| `float.c` | 软浮点全套 |
| `crc32.c` | 真实算法：常量、循环、`unsigned` 回绕 |
| `sieve.c` | 大静态数组、双层循环、无运行时依赖 |

### 怎么继续加东西

**加一条指令**（例如第 13 章的 `mul`）：

1. `RVMinInstrInfo.td`：`def MUL : RVMinRInst<OPC_MUL, ..., "mul", "$rd, $rs1, $rs2">;`
   加 TableGen 模式 `def : Pat<(mul GPR:$a, GPR:$b), (MUL ...)>`；
2. 删掉 `RVMinISelLowering.cpp` 里对应的 `Expand` 动作——否则 libcall 永远赢；
3. `scripts/rvmin-encoding-corpus.s` 加一条，跑编码门禁；
4. `llvm/test/CodeGen/RVMin/` 加 FileCheck；
5. 跑 `-O0..-O3` 与端到端脚本。

**加一个 ABI 特性**（例如 `byval`）：`RVMinCallingConv.td` 的 `CCIfByVal`、
`LowerFormalArguments`/`LowerCall` 里处理 `Flags.isByVal()`，然后扩充语料。

**优化**：`RVMinInstrInfo.cpp` 的 `copyPhysReg`、`storeRegToStackSlot` 之外的
`RVMinRegisterInfo::getRegAllocationHints`、`RVMinISelLowering` 的 `PerformDAGCombine`。

### 一句话总结

一个“最小后端”需要的不是把 RISC-V 手册抄完，而是**把 LLVM 的契约补齐**：
每个 opcode 的动作表、每个类型的合法化、每个 ABI 边界、每条汇编指令的三种表示
（MC、打印、解析）。指令集可以很小，契约必须完整。

## 当前限制（第 11 章）

- 没有跳转表（`switch` 走比较链）、没有间接跳转（`BRIND` 不支持，因此也没有
  计算 `goto`）。
- `.eh_frame` 只为“需要 unwind 信息”的函数生成；clang 的 C 代码要
  `-funwind-tables` 才有。
- 帧内偏移限制在 `[-2048, 2047]`（约 2 KiB 帧）；更大的帧需要 `RegScavenger`
  物化地址，见第 13 章。
- 没有尾调用、没有 `byval`/`sret`、没有变参函数。
- 直接调用固定 `LUI+ADDI+JALR`（12 字节），没有 `R_RISCV_CALL`/链接器松弛。
- 只支持 RV32I；没有 M/A/F/D/C 扩展（M/F/D 用 libcall 顶替）。
