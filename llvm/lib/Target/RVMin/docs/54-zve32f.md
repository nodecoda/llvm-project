# 第 54 章：Zve32f——`v4f32` 与向量浮点

## 目标

第 53 章把整数向量扩到了 LMUL=2。本章把向量寄存器堆的另一种元素类型接进来：
**32 位浮点**。

- `<4 x float>`（`v4f32`）成为合法类型，和 `<4 x i32>` 共用 128 位 `VR`；
- `vfadd.vv` / `vfsub.vv` / `vfmul.vv` 三条 OPFVV 指令；
- `vfmv.v.f`（FPR → 向量）与 `vfmv.f.s`（向量 → FPR）两条边界 move；
- 只有同时有 `+v,+f` 才生成这些指令；只有 `+v` 时退回标量软浮点；
- 编码继续与 `llvm-mc -triple=riscv32 -mattr=+v,+f` 逐字节一致。

本章**不做**：

- 向量浮点的调用约定（第 55 章只做 `v4i32` 的 ABI）；
- LMUL=2 的浮点（`v8f32`）；
- `vfdiv/vfsqrt`、`vfredsum`、masked `vf*`。

---

## 背景：OPFVV 与 OPFVF

RVV 的浮点向量指令还在 `OP-V` 主 opcode（`1010111`）里，靠 `funct3` 区分：

```text
OPFVV (funct3 = 001): vd, vs2, vs1   都是向量寄存器
OPFVF (funct3 = 101): vd, vs2 是向量，rs1 是标量浮点寄存器
```

本章用到的编码：

| 指令 | 编码（`v8,v9,v10` / `fa0`） |
| --- | --- |
| `vfadd.vv` | `[0x57,0x14,0x95,0x02]` |
| `vfsub.vv` | `[0x57,0x14,0x95,0x0a]` |
| `vfmul.vv` | `[0x57,0x14,0x95,0x92]` |
| `vfmv.v.f v8, fa0` | `[0x57,0x54,0x05,0x5e]` |
| `vfmv.f.s fa0, v8` | `[0x57,0x15,0x80,0x42]` |

`vfmv.v.f` 的 `vs2` 字段固定为 0，`rs1` 放 FPR 编号；
`vfmv.f.s` 的 `rs1` 固定为 0，`vd` 放 FPR 编号。

## 设计

### 1. 寄存器类：`v4f32` 加进 `VR`

`RVMinRegisterInfo.td`：

```tablegen
def VR : RegisterClass<"RVMin", [v4i32, v4i1, v4f32], 128,
  (add (sequence "V%u", 8, 31),
       (sequence "V%u", 0, 7))> {
  let DecoderMethod = "DecodeVRRegisterClass";
}
```

`v4f32` 和 `v4i32` 的位宽、寄存器文件完全一样，区别只在类型系统和指令选择：

- 128 位 = 4 个 f32；
- load/store 仍然是 `vle32.v` / `vse32.v`（按 32 位元素搬运，不区分整数/浮点）；
- spill/reload 仍走 `VR` 的 16 字节槽；
- 只有 `+v,+f` 同时存在时才 `addRegisterClass(MVT::v4f32, &VR)`。

### 2. 指令：OPFVV 复用 `.vv` 类，OPFVF 新增格式

三条算术指令的编码形状和整数 `.vv` 一样，只是 `funct3 = 001`：

```tablegen
let Predicates = [HasStdExtV, HasStdExtF] in {
def VFADD_VV : RVMinVVInst<0b000000, 0b001, "vfadd.vv">;
def VFSUB_VV : RVMinVVInst<0b000010, 0b001, "vfsub.vv">;
def VFMUL_VV : RVMinVVInst<0b100100, 0b001, "vfmul.vv">;
}
```

`vfmv.v.f` 需要一个“向量 + FPR 标量”的格式：

```tablegen
class RVMinVFInst<bits<6> funct6, bits<3> funct3, string mnemonic>
    : RVMinInst<(outs VR:$vd), (ins FPR32:$rs1),
                mnemonic # " $vd, $rs1", []> {
  let Inst{14-12} = funct3;
  let Inst{19-15} = rs1;
  let Inst{24-20} = 0b00000;
  let Inst{25}    = 1;
  let Inst{31-26} = funct6;
  let TSFlags{4-0} = FmtV.Value;
}

def VFMV_V_F : RVMinVFInst<0b010111, 0b101, "vfmv.v.f">;
```

`vfmv.f.s` 是反方向：`vd` 是 FPR32，`vs2` 是向量，`rs1 = 0`：

```tablegen
class RVMinVFMVFSInst : RVMinInst<(outs FPR32:$rd), (ins VR:$vs2),
                                  "vfmv.f.s $rd, $vs2", []> {
  let Inst{14-12} = 0b001;
  let Inst{19-15} = 0b00000;
  let Inst{24-20} = vs2;
  let Inst{25}    = 1;
  let Inst{31-26} = 0b010000;
};
```

### 3. 合法化：只打开 add/sub/mul 与内存

`RVMinISelLowering.cpp`：

```cpp
if (STI.hasStdExtV()) {
  addRegisterClass(MVT::v4i32, &RVMin::VRRegClass);
  addRegisterClass(MVT::v4i1, &RVMin::VRRegClass);
  addRegisterClass(MVT::v8i32, &RVMin::VRM2RegClass);
  if (STI.hasStdExtF())
    addRegisterClass(MVT::v4f32, &RVMin::VRRegClass);
}
```

动作表：

```cpp
if (STI.hasStdExtV() && STI.hasStdExtF()) {
  for (unsigned Op = 0; Op < ISD::BUILTIN_OP_END; ++Op)
    setOperationAction(Op, MVT::v4f32, Expand);
  setOperationAction({ISD::FADD, ISD::FSUB, ISD::FMUL}, MVT::v4f32, Legal);
  setOperationAction(ISD::LOAD, MVT::v4f32, Legal);
  setOperationAction(ISD::STORE, MVT::v4f32, Legal);
  setOperationAction(ISD::BUILD_VECTOR, MVT::v4f32, Custom);
  setOperationAction(ISD::SPLAT_VECTOR, MVT::v4f32, Custom);
  setOperationAction(ISD::EXTRACT_VECTOR_ELT, MVT::v4f32, Custom);
}
```

`RVMinISelDAGToDAG.cpp` 的 load/store 选择把 `MVT::v4f32` 和 `MVT::v4i32`
放在同一个分支：都选 `VLE32_V`/`VSE32_V`。

### 4. Pattern

```tablegen
let Predicates = [HasStdExtV, HasStdExtF] in {
def : Pat<(v4f32 (fadd VR:$vs2, VR:$vs1)), (VFADD_VV VR:$vs2, VR:$vs1)>;
def : Pat<(v4f32 (fsub VR:$vs2, VR:$vs1)), (VFSUB_VV VR:$vs2, VR:$vs1)>;
def : Pat<(v4f32 (fmul VR:$vs2, VR:$vs1)), (VFMUL_VV VR:$vs2, VR:$vs1)>;
}
```

pattern 本身不写谓词，但选出的指令带 `[HasStdExtV, HasStdExtF]`，
所以只有 `+v,+f` 才会匹配。

### 5. splat 与 extract

- `BUILD_VECTOR`/`SPLAT_VECTOR` 的四个元素相同 → `VFMV_V_F`；
- 四个元素不同 → 复用 `lowerVectorThroughStack`，把四个 f32 写进 16 字节私有槽，
  再以 `v4f32` 读回；
- `EXTRACT_VECTOR_ELT` 的索引 0 → `VFMV_F_S`；
- 其他常量索引 → 先把向量写进私有槽，再 `flw` 一个元素。

`lowerVectorThroughStack` 从“固定 `v4i32`”改成接受 `MVT VecVT`，
元素类型从 `Elems[0].getValueType()` 推导；这样整数和浮点共用同一条路径。

## 关键实现

### 1. 向量浮点 add

```llvm
define void @fadd4(ptr %a, ptr %b, ptr %out) {
  %va = load <4 x float>, ptr %a, align 16
  %vb = load <4 x float>, ptr %b, align 16
  %r = fadd <4 x float> %va, %vb
  store <4 x float> %r, ptr %out, align 16
  ret void
}
```

`-O2 -mattr=+v,+f`：

```asm
vsetivli zero, 4, e32, m1, ta, ma
vle32.v v8, (a1)
vle32.v v9, (a0)
vfadd.vv v8, v9, v8
vse32.v v8, (a2)
```

### 2. 标量广播与抽取

```llvm
define void @splat_store(float %x, ptr %out) {
  %v0 = insertelement <4 x float> poison, float %x, i32 0
  %v = shufflevector <4 x float> %v0, <4 x float> poison, <4 x i32> zeroinitializer
  store <4 x float> %v, ptr %out, align 16
  ret void
}
```

```asm
vsetivli zero, 4, e32, m1, ta, ma
vfmv.v.f v8, fa0
vse32.v v8, (a0)
```

抽取 0 号元素：

```asm
vsetivli zero, 4, e32, m1, ta, ma
vle32.v v8, (a0)
vfmv.f.s fa0, v8
```

抽取 2 号元素（没有直接的 lane move，走栈）：

```asm
vsetivli zero, 4, e32, m1, ta, ma
vle32.v v8, (a0)
addi a0, sp, 0
vse32.v v8, (a0)
flw fa0, 8(sp)
```

### 3. 没有 `+f` 时

同一份 IR 在 `-mattr=+v` 下会走标量软浮点：

```asm
lw a0, 12(s2)
lw a1, 12(s1)
lui t0, %hi(__addsf3)
jalr ra, 0(t0)
```

测试用 `NOF-NOT: vfadd.vv` 等断言“没有向量浮点指令”，
用 `NOF: __addsf3` 断言确实退回了软浮点。

## 常见坑

1. **`v4f32` 不能单独存在**：没有 `+f` 时不要 `addRegisterClass`，否则类型合法化
   会留下一个没有指令可选的向量类型。
2. **`vfadd.vv` 的 `funct3` 是 001**：写成整数的 000 会变成 `vadd.vv`，
   编码对照会立刻发现。
3. **`vfmv.v.f` 是 OPFVF（funct3=101）**：`vs2` 固定 0，源在 `rs1`；
   `vfmv.f.s` 是 OPFVV（funct3=001），`rs1` 固定 0，目标在 `vd`。
4. **`VFMV_V_F` 的操作数是 `FPR32`**：如果标量还是 i32（无 `+f`），
   这条指令不可用，必须让类型合法化把 f32 软化。
5. **extract 0 与 extract 2 走不同路径**：0 号有 `vfmv.f.s`，
   其他 lane 只能先存栈再 `flw`。
6. **`lowerVectorThroughStack` 不能再硬编码 `v4i32`**：用 `VecVT` 参数，
   否则 f32 的 build_vector 会得到一个整数向量。
7. **V 语料现在需要 `+v,+f`**：`check-rvmin-encodings.sh` 和
   `check-rvmin-disasm.sh` 的 V 段都已经改成 `+v,+f`，否则 FP 指令会被
   当成缺特性。
